# PacPac Implementation Plan

## Overview
Transform pacpac into a daily interactive tool that:
1. Shows which packages are not installed (missing)
2. Shows which packages are installed but not saved to the list (extras)
3. Provides an interactive menu to manage these differences
4. Uses `~/.config/pacpac/packages.yml` as the canonical package list location

## Architecture

### Core Components

#### 1. Bash Wrapper (`pacpac`)
- Entry point script that users run
- Creates config directory and default packages.yml if needed
- Runs Ansible playbook to show differences
- Provides interactive menu for user actions

#### 2. Ansible Playbook (`pacpac.yml`)
- Single playbook that orchestrates package management
- Loads configuration from `~/.config/pacpac/packages.yml`
- Executes roles in sequence: differ → saver → reaper

#### 3. Ansible Roles

##### `differ` Role
**Purpose**: Calculate and display package differences

**Vars (`roles/differ/vars/main.yml`)**:
- `pacpac_packages_all`: Combines base and extra packages
- `fleet_packages`: Packages for all machines
- `machine_packages`: Packages for specific hostname
- `applicable_packages`: Union of fleet and machine packages
- `non_aur_packages`: Filter out AUR packages

**Tasks (`roles/differ/tasks/main.yml`)**:
1. Get explicitly installed packages via `pacman -Qqen`
2. Calculate extra packages (installed but not in list)
3. Calculate missing packages (in list but not installed)
4. Display extras using printer role
5. Display missing using printer role

##### `printer` Role
**Purpose**: Format and display package lists

**Tasks (`roles/printer/tasks/main.yml`)**:
- Pretty print packages in 3 columns
- Accepts `packages_to_print` and `title` variables

##### `saver` Role
**Purpose**: Save extra packages to config file

**Tasks (`roles/saver/tasks/main.yml`)**:
1. Prompt user to save extra packages
2. If confirmed, append extras to packages.yml

**Template (`roles/saver/templates/new-packages.yml.j2`)**:
- Preserves existing config content
- Appends new packages with timestamp markers

##### `reaper` Role
**Purpose**: Remove orphan packages

**Tasks (`roles/reaper/tasks/main.yml`)**:
1. Get orphan packages via `pacman -Qqdt`
2. Prompt user for confirmation
3. Remove orphans if confirmed

### Configuration Files

#### `ansible.cfg`
```ini
[defaults]
inventory=inventory.ini
verbosity=1
editor=vim
interpreter_python=auto_silent
host_key_checking=False
roles_path=roles
callback_whitelist=profile_tasks

[privilege_escalation]
become_ask_pass=False

[diff]
always=True
context=3
```

#### `pacpac.yml` (Playbook)
```yaml
---
- name: Manage packages interactively
  hosts: localhost
  gather_subset:
    - '!all'
  vars_files:
    - "{{ pacpac_config_file | default('~/.config/pacpac/packages.yml') }}"
  roles:
    - differ
    - saver
    - reaper
```

#### Package List Format (`~/.config/pacpac/packages.yml`)
```yaml
pacpac_packages:
  - name: vim
  - name: git
    machines:
      - workstation
      - laptop
  - name: nvidia
    aur: true
  - name: bluez
    systemctl: bluetooth
    needs-manual-config: pair devices
```

## Workflow

### User runs `pacpac`:
1. Script checks for root (exits if root)
2. Determines config file location (`~/.config/pacpac/packages.yml`)
3. Creates config directory and default file if needed
4. Runs Ansible playbook showing differences
5. Enters interactive menu

### Interactive Menu Options:
1. **Edit package list** - Opens $PKGFILE in editor
2. **Show differences again** - Re-runs diff display
3. **Exit** - Clean exit

### After editing packages.yml:
- User can re-run pacpac to see updated differences
- Missing packages will be shown
- User manually installs via pacman or system update

### Saving Extra Packages:
- The `saver` role prompts to add extras to the list
- Uses Jinja2 template to preserve existing content
- Adds timestamp markers for autogenerated sections

### Removing Orphans:
- The `reaper` role identifies orphan packages
- Prompts for confirmation before removal
- Uses pacman to remove recursively

## Key Features from Training Directory

1. **Role-based architecture** - Modular design from training/roles/
2. **Variable separation** - Using vars/main.yml for complex logic
3. **Interactive prompts** - Using pause module for user input
4. **Pretty printing** - Batch formatting for readable output
5. **Template-based file updates** - Jinja2 templates for safe YAML manipulation
6. **Hostname-aware filtering** - Support for machine-specific packages
7. **AUR detection** - Separate handling of AUR vs native packages
